
## Evidence Rules (evidence-sdd)

이 규칙은 위 지침에 추가로 적용된다. 위 지침과 충돌하면 이 규칙이 우선한다.

1. **요구사항 근거 표를 채운다**: spec 템플릿의 `요구사항 근거` 섹션에 모든 FR과 SC를 한 줄씩 적는다. 행이 빠진 요구사항이 있으면 spec이 완성되지 않은 것이다.
2. **출처를 정직하게 붙인다**:
   - `명시`: 사용자 입력이나 사용자가 준 문서에 실제로 적혀 있을 때만. 근거 칸에 짧게 인용한다.
   - `관찰`: 이번 세션에서 직접 읽은 코드, 설정, 데이터에서 확인했을 때만. 근거 칸에 `파일:줄`을 적는다.
   - `추정`: 위 지침에 따라 합리적인 기본값으로 채운 모든 항목. 근거 칸에 연결된 Assumptions 항목 번호를 적는다.
   - `미확인`: `[NEEDS CLARIFICATION]`으로 남긴 항목.
3. **[NEEDS CLARIFICATION] 3개 제한은 유지한다**: 단, 기본값으로 채운 결정은 반드시 `추정`으로 남겨서 나중에 확인할 수 있게 한다. 기본값을 `명시`처럼 쓰지 않는다.
4. **검증 방법을 적는다**: 각 요구사항이 충족됐음을 무엇으로 확인할지 적는다. 검증 방법을 떠올릴 수 없는 요구사항은 테스트할 수 없는 요구사항이므로 다시 쓴다.
5. **품질 체크리스트에 항목을 추가한다**: 위 지침의 Specification Quality Checklist에 다음 항목을 넣고 같은 방식으로 검증한다.
   - [ ] 모든 FR / SC가 요구사항 근거 표에 있다
   - [ ] `명시` / `관찰` 출처에는 인용 또는 위치가 있다
   - [ ] 모든 `추정`이 Assumptions 항목과 연결되어 있다
6. **보고**: 완료 보고에 출처별 개수(명시 / 관찰 / 추정 / 미확인)를 적고, `추정` 출처인 MUST 요구사항 목록을 따로 보여준다. 사용자가 확인해야 할 후보이기 때문이다.
